# Contributing

DiaGrad is built in public and welcomes corrections, failed reproductions, data-licence findings,
and above all expertise in Filipino and other Philippine languages: no automatic metric is validated
for them, so native speakers' judgement is the main evidence here.

## Check a change the way CI does

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install pytest numpy pyyaml sacrebleu==2.6.0
PYTHONPATH=src pytest --ignore=tests/test_t1.py       # GPU/tokenizer tests run in the container (env/)
PYTHONPATH=src python -m diagrad.registry.validate
python scripts/check_publication_hygiene.py
```

## Before opening a pull request

- **Data.** Never commit dataset rows, checkpoints or held-out evaluation sentences. A new source gets a
  record in `data/registry/` (schema v2, see `data/registry/README.md`) with a pinned revision, sha256
  and the licence quoted from the source; candidates, including rejected ones, go in
  `data/registry/source_screening.json`.
- **Citations.** Add papers to `research/papers/seed.json` and run `research/tools/build_provenance.py`;
  never hand-edit `references.bib`, `registry.json` or `REFERENCES.md`.
- **Decisions.** A change that decides something gets an entry in `decisions/DECISIONS.md` and its
  evidence in `decisions/DECISIONS.md`: hypothesis, papers, measurements, and what would show
  it wrong.
- **Runs.** Write the run record before the run (`experiments/README.md`). Failed and disappointing
  runs keep their records.
- **Claims.** Label claims [paper], [measured], [inference] or [unknown]. "Not found in our searches"
  is not a novelty claim.
- **Licences.** Nothing non-commercial goes inside a model, and no training data is generated by
  non-commercial models (`research/licenses/LICENSES.md`).

A failure to reproduce an existing finding is a valuable contribution. Use the issue and PR templates.
